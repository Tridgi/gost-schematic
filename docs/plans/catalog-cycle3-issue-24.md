# Issue #24 — каталог: сплошной медный магнитопровод и консервативная provenance

**Дата:** 2026-11-12; **ветка:** `parallel/catalog-cycle3`; **baseline HEAD = integration/stage0-12:** `840576d31ac7ff201fe64144c273e3aefbb1ab83`. Старая `parallel/catalog` и исторические ветки не редактируются.

## Нормативная опора и доказательность

- ГОСТ 2.723-68, издание мая 2002 с изм. №1–3, п.5, табл.1, поз. 2а, примеч.1: немагнитный металл изображён сплошным штрихом и обозначен химическим символом (для меди `Cu`). Позиция 2в того же листа — отдельный **штриховой** магнитодиэлектрик. [PDF лист 2/10](https://helpeng.ru/public/normdoc/eskd/gost_2.723-68.pdf#page=2).
- ГОСТ 2.723-68, п.6, табл.2 поз.7 (медный подстроечный сердечник) vs поз.6 (магнитодиэлектрический) — два различных исполнения; поз.3 показывает **альтернативные** места одиночного отвода с «или» (не оба одновременно), а поз.4 иллюстрирует два скользящих контакта и формулирует «например, двумя». [PDF лист 3/10](https://helpeng.ru/public/normdoc/eskd/gost_2.723-68.pdf#page=3).
- Дополнительная справка: `docs/standards/issue-18-high-risk-inductors.md`, `docs/standards/issue-18-rule-cards.json`. Все упомянутые УГО остаются `DRAFT/BLOCKED`, нормы не задают координаты конкретных отводов, положение `Cu` и геометрию T-ограничителя регулирования.

Для Cu — **непрерывная** `StyledLine` с пустым `dash_pattern_um`; для магнитодиэлектрика — сохранить исходную пару `(2000,1100)` мкм как **проектный**, не «нормативный» паттерн. Остальные виды и генераторы без изменений.
2. В двух собственных JSON `inductor.double_tapped` и `inductor.sliding_contact` изменить только `normative_relation` с `table_2_example` на `editorial_adaptation`; уточнить текст `normative_basis` для буквального «или» и «например, двумя». Не менять `tap_turns/slider_turns`, `revision`, параметры геометрии и схемы.
3. Обновить существующий `tests/test_inductor_family.py` и создать независимый негативный регрессионный модуль. Зафиксировать нетронутые `GraphicPin`, `PhysicalPin`, `TerminalFunction`, `ConductorTopology`, отсутствие core в `conductor_indices`, прежние габариты/координаты, повороты/отражения, constant annotation `Cu`, и статус `DRAFT`. Негативные фикстуры: Cu→dashed, исчезнувшая `Cu`, magnetodielectric→solid, сердечник ошибочно добавлен в электрический граф, неверная provenance.
4. Создать отдельный генератор `examples/review_copper_core_cycle3.py`, который на штатных функциях строит независимые чистые/диагностические SVG двух **подстраиваемых** катушек `trim_copper` / `trim_magnetodielectric` с постоянной надписью `Cu` и JSON-манифестом. Тесты рендера проверяют `stroke-dasharray`, общее число дуг, содержимое `text` и корректность диагностической прослойки. Нет нового API и правок `rendering/*`.
5. Запустить Ruff, pytest, полный каталог-аудит **19 DRAFT/0 hard errors**, wheel CI Python 3.12/3.13. Draft PR только к `integration/stage0-12`, отчёт Issue #24, без merge.

## Нерешённые нормативные вопросы (вне scope)

- Форма окончания диагонального знака подстройки Cu, реальные координаты/размеры и текстовое положение `Cu` **не утверждены**. Не заменять наконечник «на глаз».

- `inductor.double_sliding` остаётся прямым примером **класса**, но его реальные геометрические координаты не сертифицированы.
- Никакой `APPROVED` и никаких изменений общих `core/*`, `model/*`, `rendering/*`, `standards/*` или внешних электрических соединений.
