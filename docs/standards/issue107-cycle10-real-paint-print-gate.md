### Машинный нормативно-печатный контракт для 13 применённых профилей

В этом цикле `scripts/eskd_cycle10_native_print_gate.py` берёт каждую строку прямо из **настоящего** YGO manifest, а не из собственной выдуманной таблицы: `src/gost_schematic/catalog/source_profiles/tl494_source_20261114.json`, frozen original SHA указан внутри. Критерий: фактическая ссылка на `data-reference`/профиль `symbol_id`, точный тип и ориентация из manifest, фактические SVG/PNG owner. Результирующий JSON создаётся в workflow и перечисляет отдельное `PASS_DRAFT` либо `BLOCKED_UNCALIBRATED` на каждую исходную позицию.

| Позиции на исходной схеме | Конкретная норма | Физико-графический позитивный контроль | Блокирующая проверка |
|---|---|---|---|
| VD1 — `diode.schottky`, R90 | [ГОСТ 2.730-73, табл.4/9 и табл.5/9](https://www.cad.dp.ua/gost/files/GOST2.730-73.pdf#page=4) | A сверху/K снизу; обе катодные загнутые ножки сохраняют несимметричную исходную ориентацию | Собственный print/PDF источник 1:1 не откалиброван; электрически целесообразный VD1 не подтверждён |
| VT1 — `transistor.mosfet_n_enh`, R0 | [ГОСТ 2.730-73, табл.8/3б](https://www.cad.dp.ua/gost/files/GOST2.730-73.pdf#page=6) | G/D/S = три физических истинных вывода, gate не замыкается на channel, отдельная стрелка и внутренний source junction не создают ложный PinRef | Изображение корпуса/подложки и настоящая source-photo точка не приняты 1:1 |

| C4, C7 — `capacitor.fixed` | [ГОСТ 2.728-74, табл.4/1](https://helpeng.ru/public/normdoc/eskd/gost_2.728-74.pdf#page=7) | Тонкие обкладки, **без** знака полярности | Не менять на `electrolytic` ради «красоты» |
| L1, L2 — `inductor.ferromagnetic` | [ГОСТ 2.723-68, табл.1/2а и табл.2/8](https://docs.guap.ru/regdocs/stands/gost_2-723-68_ver-2010.pdf#page=6) | Непрерывный сплошной ферромагнитный сердечник, не air-core, не dashed magnetodielectric | Четыре витка и радиус 2мм — настройки проекта, а не безусловная геометрическая величина ГОСТ |

| R5 — `resistor.variable`, R90 | [ГОСТ 2.728-74, табл.1/4](https://helpeng.ru/public/normdoc/eskd/gost_2.728-74.pdf#page=2) | Три реальных контакта, отдельный wiper; правильное имя/перемещение не соединяет ложные провода | Wire clearance и реальная 15-Net электрическая трассировка не приняты |

**Общий провод:** `COMMON/0V` есть источник электрического имени/сети, НЕ автоматическое `PE`/корпус/earth. Типы по [ГОСТ 2.721-74, табл.6б](https://ohranatruda.ru/upload/iblock/328/4294852095.pdf#page=11) самостоятельные. В реальном исходном SVG не добавлять подтверждённое защитное заземление из отсутствующей информации. При продолжении `b` имеются только две нерезистивные графические метки `b-X2`, `b-R5`: **они не физические точки и не доп. Net**. Их нормативный контекст должен проверяться с учетом [ГОСТ 2.701-2008 §5.5.3–5.5.4](https://rosgosts.ru/file/gost/01/100/gost_2.701-2008.pdf#page=9), реальный источник same-sheet.

### Фактическая проверка мм (не бумажные обещания)

Новый тестовый скрипт берёт **настоящие 91** `<line data-layer="wires" data-net="..." data-wire-index="...">` из SVG owner, заново вычисляет все **4095** пар, без подмены картинкой; контроль принятых форматов требует 0,2–1,0 мм толщины штриха, source-matched индексы/Net, H/V, реальный положительный проектируемый параллельный участок. Считает ink-edge `gap = center_distance - (width_a + width_b)/2`; разные Net и соседние параллельные линии должны иметь ≥3мм. Конкретные настоящие 5 негативных нарушений сравниваются с actual owner manifest по **index, Net и микрометрам**. Старый 91-wire НЕ превращается в «новый 15/15» от сохранения структурных инвариантов.

**ГОСТ 2.701-2008 §5.3.4:** 3мм именно соседние параллельные проводники с общей проекцией, 2мм отдельные УГО, 1мм линии УГО. Измерение **действительных 2/1 мм во всём full native листе пока BLOCKED** — это не выводится из проверки одних проводников или `layout.valid`. Текст 2.5/3.5мм проверить по реальным OpenGOST чернилам; точное `font_sha256` и Type A `h=3.5мм` валидирует новый прогон, но не гарантирует отсутствие каждой коллизии.

**Печать:** корневые SVG `width/height/viewBox` должны иметь тождественную физическую шкалу, новые PNG — действительную ширину `round(mm * 300 / 25.4)` пикселей. 300 DPI — требование автоматизированного QA этой команды, не самостоятельный ГОСТ-минимум. Должно быть 23 уникальных `<g data-layer=symbols data-reference=...>`, 16 `<line data-pin-number=...>` DA1, 37 токовых junction dots и **0 зелёных редакторских квадратов в clean**, 16 точно source PinRef-координатных квадратов в foreground debug. `PWM` должен быть `(0,-1)` по базису текста; право самостоятельно поворачивать только функцию нормативно всё ещё BLOCKED.

### Специализированный интеграционный CI

[`.github/workflows/eskd-cycle10-native-print-gate.yml`](../../.github/workflows/eskd-cycle10-native-print-gate.yml) делает настоящий **read-only Git worktree** PAINT exact SHA, подставляет в этом изолированном рабочем каталоге оригинальные исходные `Circuit` (из original SHA) и IC/YGO owner code (из указанных выше SHA), запускает genuine full renderer, а затем **самостоятельный ESKD скрипт** проверяет именно выданный owner SVG и реальные 300DPI PNG. Никаких ручных правок рисунка или смешивания кадров старого и нового оригинала; файлы production не копируются/изменяются в PR #112.

Тесты: `tests/test_standards_cycle10_native_print_gate.py` обеспечивают правильный чистый/diagnostic слой, 23/15/16/91 source contract и отрицательные примеры: 2.999/3.000mm, X против параллельных линий, инверсию PWM, ненадёжный pin index, фальшивый PE, неправильную b связь, недостающие рефдес/Net, неверный шрифт и пропуск реального исходного SVG.

**Результат специализированного CI с успешными проверками должен прямо содержать `release_verdict: NO_GO`, `print_hard_3mm_parallel_gaps: FAIL`, `native_owner_clean_and_debug: PASS_DRAFT`, `normative_rules_and_user_bitmap: BLOCKED`**. **Успешный workflow — это PASS достоверности и отрицательного обнаружения, НЕ PASS полной схемы.** Если actual owner вывод не совпал с замороженной версией или source tests сломаны, CI обязан RED с причинами; не восстанавливать проход путём выключения тестов.
