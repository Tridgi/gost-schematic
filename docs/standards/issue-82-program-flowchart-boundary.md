# Issue #82 — предварительная нормативная граница алгоритмической блок-схемы и электрической Э1

**Статус: PRELIMINARY / DRAFT / NOT IMPLEMENTED.** Это не задание YGO 2 на создание УГО Э3 и не допуск к генератору `AlgorithmDiagram`.

## Нормативный приоритет

1. **[ГОСТ 19.701-90 (ИСО 5807-85)](https://protect.gost.ru/gost/details/0c85e066-f89e-433d-a6d3-b7f746bd0c)**, действующий, [копия оригинальных рисунков](https://www.swrit.ru/doc/espd/19.701-90.pdf). **§2.2.1–2.2.2** — схема программы отображает **последовательность операций** и **поток управления**. §2.1 отличается: схемы **данных** отображают пути данных и операции над ними. Указание «блок-схема алгоритма» без уточнения вида не даёт права объединять оба типа документа.
2. **[ГОСТ 2.702-2011 §5.1](https://protect.gost.ru/gost/details/d9c1c334-2a90-45cb-ac00-c31da92d706b)** — электрическая структурная **Э1**: функциональные части **электротехнического изделия** и связи между ними. Семантика — не управление операторами программы. **Э3** — электрические физические цепи и `PinRef`. Семейство ЕСПД должно быть отдельным `document_type`, **никогда не `Э1` по умолчанию**.
3. **[ГОСТ 19.101-77 §2.2 таблица 2](https://ru.wikisource.org/wiki/ГОСТ_19.101%E2%80%9477)**: схема алгоритма входит в содержание вида **«Пояснительная записка»** среди документов ЕСПД; отдельный рисунок алгоритма не становится автоматически самостоятельной Э1.
4. **[ГОСТ 19.104-78](https://files.stroyinf.ru/Index/32/32404.htm)** — основные надписи, ЛУ/титульный лист ЕСПД; **[ГОСТ 19.105-78](https://protect.gost.ru/gost/details/500f8c05-0b04-40fc-a049-4212eae807c3)** — общие требования; **ГОСТ 19.106-78** — нормы печатного программного документа по назначенному виду, проверить отдельно. **Форма 1 ЕСКД 185×55 мм не является обязательным штампом всех программных схем**. Использование формы ЕСКД возможно лишь при явном документированном профиле и проверке соответствующих стандартов.

## Пример «Блок-схема программы. Одномерные массивы»

В Issue #82 указаны сюжетные блоки **начало/конец, ввод n и d, формирование массива, проверка условий, циклы, нахождение min/max, вывод массива/результата, соединители, линии направления и титул**. Ни сам чертёж, ни полный код пользователем в текущей задаче не предоставлены для независимого геометрического обмера; ниже выводы опираются на **описание** и первоисточник, а не на выдуманный точный SVG.

| Операция в «Одномерных массивах» | Правильный тип символа ГОСТ 19.701-90 | Проверка |
|---|---|---|
| Начало и конец | **Терминатор**, §3.4.2 | Отдельные точки входа/выхода; не generic Э1 прямоугольник |
| Ввод n,d; вывод массива, min/max | **Данные** (параллелограмм), §3.1.1.1; при конкретно ручном вводе §3.1.2.5 | Символ должен соответствовать источнику данных, не «датчик Э1» |
| Инициализация i=0, min/max | **Подготовка**, §3.2.2.3, если цель именно воздействовать на последующее управление; либо **Процесс**, §3.2.1.1, если выполняется обычное присваивание | Не универсализировать одну фигуру для любого присваивания |
| A[i]=…, update min/max, i=i+1 | **Процесс**, §3.2.1.1 | Прямоугольник как операция над данными, не устройство |
| i<n? / A[i]<min? / A[i]>max? | **Решение**, §3.2.2.4 | Ромб с явно идентифицируемыми альтернативными выходами, **§4.3.1.2** |
| Циклический перебор индексов | Возможны **границы цикла**, §3.2.2.6, две части с общим ID; либо решение и явная возвратная связь | Не навязывать парную форму как единственно законную для любого цикла |
| Вызов генерации/поиска как отдельной функции | **Предопределённый процесс**, §3.2.2.1 при реально отдельно определённой подпрограмме | Не применять, если отдельное определение не существует |
| Обрыв длинной связи и продолжение | **Соединитель**, §3.4.1, у обеих частей одинаковый уникальный ID | Простое X не является соединителем |

## Обязательные правила линий алгоритма — не подменять Э1

- **ГОСТ 19.701 §4.2.1:** поток слева направо и сверху вниз — стандартный; **при ином направлении стрелка обязательна**. Для Э1 ГОСТ 2.702 §5.1.3 направления процесса **рекомендуется** указывать стрелками; это **не тот же самый пункт**.
- **ГОСТ 19.701 §4.2.4:** входящие линии подходить **слева/сверху**, исходящие — **справа/снизу**, линии направлять к центру символа. **Это алгоритмическая, а не электрическая Э1 норма**. Она не определяет неизменяемый публичный API или математическую единственную позицию `t=1/2` на каждой стороне.
- **ГОСТ 19.701 §4.2.2:** пересечения линий не имеют логической связи друг с другом. Соединения не выводятся из простой геометрической точки X.
- **ГОСТ 19.701 §4.3.1.1–4.3.1.2:** допустимы несколько выходов и разветвление, **каждому исходу нужно значение условия**. Для двух исходов `Да/Нет` требуется однозначное соответствие условию, для нескольких — значения/ссылки.
- **ГОСТ 19.701 §4.1.4:** минимальный понятный текст внутри символа, читаемый слева направо и сверху вниз; переполнение — отдельная поясняющая/комментарий, а не бесконечное уменьшение глифов.
- **ГОСТ 19.701 §3.4.1:** парные соединители имеют одинаковое уникальное обозначение. **§3.2.2.6:** границы цикла состоят из двух частей с одним ID.

## Архитектура после отдельного согласования

**Только RFC:** `AlgorithmDiagram` / `FlowNode` / `ControlFlowEdge`, семантические типы `terminal,data,process,decision,preparation,loop_boundary,connector,predefined_process` строго по области определения ГОСТ; отдельные условные значения исходов decision; циклы без ложного DAG-only ограничения; непрерывность и достижимость CFG, привязка отдельных блоков к исходному коду/диапазонам строк; versioned JSON. **Не импортировать в `gost_schematic.structural` Э1**, не трогать существующий `Circuit` Э3.

**BLOCKED до программы и исходного изображения:** точный flow chart алгоритма «Одномерные массивы», размеры символов, стрелки возвратов, значения ветвей, доказательство семантической эквивалентности кода, титул/лист и статус `APPROVED`. Не обещать двустороннее `code ↔ flowchart` без AST/CFG трассировки и ограничений языка; не писать генератор в этой задаче.

**Передача координатору:** нормативное разграничение **готово к рассмотрению**; решение о виде документа, RFC семантики и принятых форматах листов должно быть отдельным. **0 новых графических символов и 0 генераторов**.
