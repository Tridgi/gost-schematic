# Issue #91 — углублённая независимая экспертиза нормативных первоисточников, Cycle 7 (вторая ревизия)

**14.11.2026, ESKD.** Уточнение к [основному пакету 107 кандидатов](issue-91-cycle7-electronics-review.md) и [карточкам](issue-91-cycle7-electronics-cards.json), а не их замена. **Ни одна карточка сама по себе не подтверждает геометрию готового УГО; все графические реализации DRAFT, обязательные оттиски и конкретные datasheet-проверки BLOCKED.** [Машиночитаемые заключения и исключения](issue-91-deep-source-audit.json).

Контролируемые источники: издание ГОСТ 2.743-91 с [сканами печатных с. 2–4, 14, 41](https://lepton.ru/GOST/Data/190/19085.pdf#page=4); [ГОСТ 2.759-82, с изменением №1](https://files.stroyinf.ru/Data2/1/4294849/4294849490.pdf); [ГОСТ 2.730-73, изменения №1–4, май 2002](https://www.cad.dp.ua/gost/files/GOST2.730-73.pdf); [ГОСТ 2.728-74, изменения №1–2](https://helpeng.ru/public/normdoc/eskd/gost_2.728-74.pdf); [ГОСТ 2.727-68, изменения №1–2](https://www.nuvis.com.ua/GOST_2.727-68_ESKD.pdf); [ГОСТ 2.755-87](https://eelib.narod.ru/eskd/GOST_2.755-87.pdf); [ГОСТ 2.721-74, 2008](https://ohranatruda.ru/upload/iblock/328/4294852095.pdf); [ГОСТ 2.709-89](https://files.stroyinf.ru/Data/194/19467.pdf); официальные карточки [2.702-2011](https://protect.gost.ru/gost/details/d9c1c334-2a90-45cb-ac00-c31da92d706b), [2.710-81](https://protect.gost.ru/gost/details/6fecf975-2fad-4d4e-ac72-176c00caa188), [2.304-81](https://protect.gost.ru/gost/details/2acb3258-c28c-4e4a-b7ac-208043f2d95e), [2.701-2008](https://protect.gost.ru/gost/details/87f1f382-a055-48b7-ae80-f359ff5e1f4e).

**Применимость редакций:** по состоянию на 14.11.2026 для шрифта используется ГОСТ **2.304-81** (с изменениями); [ГОСТ Р 2.304-2026](https://protect.gost.ru/gost/details/f744cc7d-56c7-4930-98c0-afeedd135827) введён с **01.10.2027** с правом досрочного применения, но его нельзя молча сделать выбранным профилем всех документов. В 2.730-73 приложение 1 исключено изменением №4; приложение 2 **справочное**, и не даёт автоматической абсолютной сетки в мм. Направление «рекомендательное/обязательное» устанавливать по заголовку приложения и смыслу пунктов, а не по способу генерации SVG.

## 1. Микросхемы DD/DA: чертежи 3 и 4, §2.1.2 и §2.1.6 ГОСТ 2.743-91

**Первоисточник проверен графически на печатной с.3, PDF нулевая стр.3.** П. **2.1.2** требует в первой строке *основного поля* обозначение функции; следующие строки — сведения по ГОСТ 2.708; в дополнительные поля — назначение выводов. В **п. 2.1.6** прямо допускается другая ориентация УГО с **входами сверху и выходами снизу (черт.3)**. **Черт.3 содержит два разных допустимых изображения при верхних входах и нижнем выходе**: в одном символы/надписи читаются горизонтально относительно листа; в другом значительная часть текста показана повёрнутой вместе с иной компоновкой УГО. Следовательно:

| Проверяемый вопрос | Экспертный вывод |
|---|---|
| Поворот УГО как целого на 90°, включая рамку и смысловое расположение полей | **CONDITIONAL PASS**: допустима *ориентация*, предусмотренная п.2.1.6/черт.3, при согласованном положении входов/выходов, читаемости и реальных номерах |
| Входы **сверху**, выходы **снизу** | **PASS**, п.2.1.6, черт.3 (также аналоговый ГОСТ 2.759-82 п.1.8) |
| Только `rotate_function_text_only=90` в **неизменённом** горизонтальном УГО | **BLOCKED**: §2.1.2 + черт.3 **не являются** универсальным разрешением независимо повернуть произвольную надпись в середине |
| Вертикально расположенное обозначение функции при согласованной перестановке/повороте всего УГО | **CONDITIONAL PASS**: на нижнем варианте черт.3 вертикальная компоновка надписей есть, но проект обязан совпадать именно с этим профилем, а не обобщать на все углы, функции и подписи |
| Поворот **всех** подписей `pin name`, физических номеров, `DD1` и любого Cyrillic текста без проверок | **FAIL как нормативное утверждение**: отдельного универсального правила здесь нет; §2.1.9 и 2.304 предъявляют требования шрифта/читаемости, §2.3.12 — номеров |
| Обратная ориентация **входы справа/снизу; выходы слева/сверху** | **PASS только при стрелках** на линиях выводов/связи, указывающих распространение информации, и функциональном обозначении **как на черт.4**, согласно примечанию п.2.1.6 |
| Просто развернуть стрелки/изображение без пересмотра функции | **FAIL**, потому что черт.4 меняет соответствующее смыслу функциональное обозначение, а не только геометрию |

**Рекомендуемая реализация PAINT #93:** *явно перечисленные профили* `STANDARD_LEFT_IN_RIGHT_OUT`, `TOP_IN_BOTTOM_OUT_TEXT_UPRIGHT`, `TOP_IN_BOTTOM_OUT_FIG3_ROTATED_TEXT`, `REVERSED_WITH_FLOW_ARROWS_FIG4`. **Не** вводить `arbitrary_rotate_text_any_angle` с меткой GOST. Для каждого профиля фиксировать `source_ref="2.743-91 §2.1.6 fig.3/4"`, расположение первого символа функции в основном поле, базовую линию, полное ink bbox, физический номер и направление читаемого текста. Неразрешённые комбинации или long text → `BLOCKED_UNSUPPORTED_TEXT_ORIENTATION`, без silent fallback.

### Номера контактов / дополнительные поля / реальные размеры

- **§2.1.1** прямоугольная форма DD, 0–2 доп. поля слева/справа. **§2.1.3, табл.1 поз.1–4:** основное; +правое; +левое; +оба, возможны горизонтальные зоны, их количество не ограничено. Без линий-разделителей при однозначности — не менее **двух физических графических знаков соответствующего шрифта** между соседними обозначениями на одной строке, **не 2 мм**.
- **§2.1.4:** обычно входы слева, выходы справа; двунаправленные/нелогические — слева/справа. **§2.1.5** запрещает подводить линии выводов *на уровне стороны прямоугольника* и размещать стрелки непосредственно у контура — поэтому corner ports FAIL.
- **§2.3.12:** физический **номер** над линией, **слева для входов, справа для выходов от контура/указателя**, либо **в разрыве линии**; это не номер логического `visual_row`, не `port_label`, не номер `DD1`. Вариант TOP/BOTTOM требует отдельного графического профильного решения и сравнения с оригиналом: нельзя механически приклеить правило "на странице всегда выше" к повёрнутому штриху и объявить APPROVED.
- **§2.2.1:** **число знаков обозначения функции НЕ ограничено**, предпочтительно минимум для однозначности; `max_chars=10/32` и подрезание/ellipsis по ГОСТ — **FAIL**. **§2.1.7:** реальный размер формируется количеством контактов, интервалов, строк и измеренным размером **чертёжного** шрифта, а не только числом ножек.
- **§2.1.8 и рекомендуемое приложение 5, табл.19 поз.1:** относительный минимальный шаг **≥2M** на модульной сетке, выбор `M=2.5мм` у PAINT #93 **редакторский**; это не размер, установленный в миллиметрах самим 2.743-91. В то же время §2.1.8 отсылает к соотношениям приложения — не считать приложение «не относящимся к проекту» при выбранном профильном применении.
- **§2.3.10–2.3.11:** **NC** с особым указателем; питание либо указанной информацией, либо общим блоком/секцией/отдельным контуром по черт.6 — при всех вариантах один и тот же *реальный* `PinRef` сохраняется в памяти корпуса. §2.4.2 при логически равнозначных контактах допускает отсутствие дополнительных полей и подписей при условиях равного шага/однозначной функции.
- **2.759-82 §§1.1–1.4, 1.8–1.11** наследует цифровые требования, но функция первой строки записывается из латинских букв/цифр/спецзнаков **без пробелов**; табл.2–4 задают аналого-математические метки (усиление, интегрирование, суммирование, деление), это не любые текстовые имена.
- **2.710-81** DA/DD — позиционная идентичность типа изделия; **2.702-2011 §5.3.21** реальная нумерация из документации изделия, для условной требуется пояснение; эти нормы не делают номера входов `1..40` истинным pinout конкретной микросхемы.
- **2.304-81** реальная высота прописной буквы `h` требует измерения глифа и проверенного шрифта; `font-size` SVG является размером em и не равен физическому `h` автоматически.
- **2.701-2008 §5.3.4**: чернильный просвет от отдельных штрихов: ≥1мм внутри УГО, ≥2мм между УГО, ≥3мм для параллельных линий электрической связи; `axis_distance` обязан учитывать полу-сумму ширин штрихов.

**Критическая оговорка к первым 107 карточкам:** их исходный `normative_rule_status=PASS` отражал лишь наличие *указанного источника* — в настоящем аудите отдельно помечаются **scope-limited** случаи, когда из рисунка эффекта или схемы **нельзя вывести готовый физический УГО**. Не повышать такие карточки в `APPROVED` автоматически.

## 3. Резисторы, FU и физические разъёмы

- [ГОСТ 2.728-74 **табл.1 поз.4** и три примечания](https://helpeng.ru/public/normdoc/eskd/gost_2.728-74.pdf#page=2): **стрелка = подвижный контакт; неиспользуемый вывод ДОПУСКАЕТСЯ НЕ ИЗОБРАЖАТЬ на схеме**, и при реостатном включении допустимы специальные варианты. **Это не разрешение удалить третий physical WIPER/END из `PartDefinition` изделия**, если он действительно физически существует. *Следствие:* нормативная претензия «в любом УГО обязательно нарисованы все три вывода» — **FAIL**. Реальная `Circuit.Net` определяет использование, а `SymbolDefinition` может не показывать неиспользуемый графический вывод **только по явной документированной стратегии**. При включении как реостата произвольное автоматическое соединение W с концом — **FAIL**.
- [ГОСТ 2.728 табл.1 поз.9 / табл.6 поз.5](https://helpeng.ru/public/normdoc/eskd/gost_2.728-74.pdf#page=10) — подстроечный резистор с конкретным **графическим** регулированием, стрелка/отгиб не является 4-м электрическим выводом. В размерной таблице поз.3 показан **45°** наклон обычной стрелки; поз.5 отдельные размеры конструкции регулятора. **20×4мм** относится к функциональному потенциометру **табл.6 поз.6**, не к любому `resistor.variable`.
- [ГОСТ 2.727-68 табл.3 поз.1 и 2](https://www.nuvis.com.ua/GOST_2.727-68_ESKD.pdf#page=3): поз.1 **пробивной**, поз.2 **плавкий** предохранитель. В таблице специальное примечание допускает **толстую линию стороны, остающейся под напряжением**; это **не автоматически левый контакт, не физический третий контакт**, а контекст документа. `fuse.general` имеет два реальных разрыва цепи через защитное изделие, **не** «прямой wire» и не условно замкнутую нулевую сеть.
- [ГОСТ 2.755-87 табл.5 поз.1(1)](https://eelib.narod.ru/eskd/GOST_2.755-87.pdf#page=9): отдельные **штыревые/гнездовые** контактные детали с несколькими допустимыми видами графики. [Табл.6 поз.1–5](https://eelib.narod.ru/eskd/GOST_2.755-87.pdf#page=10) — сочленённые физические пары, четырёхпроводные, многоконтактные, коаксиальные варианты. **Числа 1–4 внутри прямоугольников — номера реальных контактов в образце**, НЕ заводской pinout каждого XP/XS.
- [ГОСТ 2.710-81](https://protect.gost.ru/gost/details/6fecf975-2fad-4d4e-ac72-176c00caa188) — коды `DA`, `DD`, `VD`, `VT`, `FU`, `XP`, `XS` определяются типом изделия; нельзя обозначать любой безфизический обрыв как `XP1`.

## 4. ГОСТ 2.721-74 и 2.709-89 — маркировка, адрес, направление, продолжения

**Графический оригинал:** 2.721-74 **табл.6в поз.5** — несоединённое прямое X под 90°; **поз.6 и прим.2** — T с одним ответвлением допустимо без точки; **табл.6в поз.8** — обрыв электрической связи стрелочным указателем **с X-данными о продолжении, требующимися по месту**. Это **рисунок именно обрыва**, а не приказ каждому имени цепи добавлять стрелку.

**ГОСТ 2.709-89 §5.13**: буквенно-цифровое имя участка цепи **над горизонтальной**, **слева от вертикальной** линии; в технически обоснованных случаях над вертикальной допускается, **не универсально**. **§5.14:** вместо обозначения могут использоваться **взаимные адреса присоединения**: у начала участка — адрес конца, у конца — адрес начала. **Адрес** здесь — буквенно-цифровое обозначение **элемента, устройства или функциональной группы** по ГОСТ 2.710. Оригинальные **черт.10,11** показывают, например, `R1`, `C3` и взаимную привязку `A7:X...`; **черт.12** показывает *смешанное* обозначение: имя цепи и адреса присоединений. Строка `sheet:zone`/координата листа может быть **редакторским дополнительным навигационным реквизитом**, но без проверенного контекста **НЕ** выдавать её за единственную «нормативную форму §5.14».
  
| Вариант | PASS / FAIL / BLOCKED |
|---|---|
| `R1` на одном конце, `C3` на противоположном — адреса реальных соединений и `NetId` совпадают | **PASS** для принципа взаимного адреса §5.14; детали нумерации/двоеточия по ГОСТ 2.710 |
| `A7:X16` / `A4:X11` при действительно существующих документационных элементах/зажимах | **PASS** для типа адреса по примеру черт.11; точная пунктуация зависит от формальной семантики обозначений |
| Имя цепи + адреса по черт.12 | **PASS** как разрешённый смешанный вариант |
| Только `SHEET_2:ZONE_A3` названо «строгий ГОСТ 2.709 §5.14» | **BLOCKED**: это project navigation address без подтверждённой семантики элемента/устройства/группы |
| Два разных физических `NetId` с одинаковой надписью автоматически замкнулись | **FAIL**: графическое совпадение не электрическая истина |
| Стрелка у каждого текстового имени цепи даже без обрыва | **FAIL** как заявленное требование ГОСТ: табл.6в/8 относится к изображаемому обрыву |
| Реальные XP/XS стали «беспроводным» переходом линии | **FAIL**: требуется `PartDefinition+PhysicalPin` у каждого физического контакта, состояние сочленения/электрический граф |

**Когда стрелка?** Для **обозначения графического обрыва по табл.6в поз.8** — графическая форма источника со стрелкой и требуемыми данными о продолжении. Для обычной подписи цельного участка цепи **§5.13 — стрелка НЕ обязательна**. Указатель направления сигнала по ГОСТ 2.721 табл.1 / ГОСТ 2.743 прим.2.1.6 нужен при соответствующей направленной семантике/обратной ориентации, **не всякому электропроводу**. **Точное** оформление взаимных адресов и напечатанного стрелочного указателя нуждается в независимом 1:1 графическом сопоставлении конкретного реализованного листа.

## 5. Issue #100 — зелёные зоны на концах проводов

**Экспертный статус: PASS как отделение UI от ЕСКД, FAIL при экспорте редакторского цвета как ГОСТ-разметки.** Зелёные квадраты/точки на физическом `PinRef`, допустимом `wire endpoint`, `junction` — **интерактивные области наведения и snap**; на чертежах ГОСТ они **не являются** дополнительными условными графическими обозначениями, не заменяют чёрную точку **подлинного** соединения на схеме из 2.721 табл.6в поз.6, не создают электрическую цепь сами. Радиус **8–12 CSS px** лишь предлагаемый UX default, не миллиметровая норма.

**В чистом SVG/PDF/печати запрещено сохранять:** зелёные фоновые кружки/квадраты, полупрозрачные цельовые зоны, hover/crosshair, фокус-кольца, красно-зелёную диагностику, dashed proposed-wire route, IDs редакторского выделения/drag handles и RGB-пометки NC. **Допустимый явно включаемый непечатный слой:** `data-layer="editor-connection-targets"` c immutable `PinRef+world_Point+status`, `data-layer="diagnostics"` c source SHA, статусами и уникальными ID, отдельно от производственного документа; `export(clean)` обязан вырезать эти слои целиком. При совпадении нескольких вариантов snap — reject ambiguity, не auto-net merge. Для недоступности цветового зрения или черно-белого экрана статус не должен кодироваться только цветом.
