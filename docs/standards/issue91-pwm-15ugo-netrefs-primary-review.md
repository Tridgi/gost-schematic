## 1. P0. Вертикальный корпус микросхемы, слово `PWM` и независимые оси параметров

**Контролируемый первоисточник**: [ГОСТ 2.743-91, официальный репринт 2003, PDF p.3: §2.1.4–2.1.9, **черт.3/4**](https://lepton.ru/GOST/Data/190/19085.pdf#page=4), [PDF p.2: §2.1.2–2.1.3, табл.1](https://lepton.ru/GOST/Data/190/19085.pdf#page=3), [§2.2.1/§2.2.6](https://lepton.ru/GOST/Data/190/19085.pdf#page=8), [§2.3.12](https://lepton.ru/GOST/Data/190/19085.pdf#page=15); аналоговые [ГОСТ 2.759-82, редакция с Изм. №1 §§1.1–1.8](https://files.stroyinf.ru/Data2/1/4294849/4294849490.pdf#page=1).

**Три действительно отдельные проектные переменные:** `body_aspect = width_um,height_um`, `pin_side_layout = (LEFT,RIGHT,TOP,BOTTOM)`, `main_function_text_orientation = 0°|90°|270°`. Архитектура редактора **может** хранить их независимо; это **не доказывает нормативной свободы** для любой комбинации. **Печатный профиль** должен валидировать совместное состояние `(body, fields, lead_sides, text orientation, function meaning, flow arrows)`, а не каждое поле по отдельности.

| Неподвижный корпус H>W; те же стороны контактов | Вердикт | Стандарт и граница применения |
|---|---|---|
| **`PWM` 0° горизонтально**, входы LEFT, выходы RIGHT | **PASS С УСЛОВИЯМИ** | §2.1.2 функция на первой строке основного поля; §2.1.4 стороны; §2.1.7 размеры H/W от реального количества выводов, строк/пробелов/размера шрифта. В вертикально вытянутой рамке само соотношение H>W НЕ запрещено, но эта пропорция **не нормативная обязанность**. |
| **`PWM` 90° вертикально**, точно тот же корпус/те же LEFT/RIGHT pin sides; вращается только функция | **BLOCKED** | §2.1.6/черт.3 на оригинале показывает две **компоновки** с TOP inputs/BOTTOM outputs, в одной надписи горизонтальны, в другой повёрнуты. Нет универсального пункта «в любом неориентированном блоке поворачивать только функцию на 90°». Типографская `h` не выдаёт разрешения на изменение ориентации. |
| **`PWM` 270° вертикально в обратную сторону** при прочем неизменном | **BLOCKED** | Имеющиеся черт.3/4 не дают универсального independently rotated reversed-function mode; отдельного подтверждения для этого фиксированного layout **не получено**. |
| **Контекстное `FIG3_TOP_BOTTOM_VERTICAL`**, верхние входы/нижние выходы и соответствующее полевое представление | **CONDITIONAL PASS только рисунок-совпадающего варианта** | §2.1.6 черт.3, визуально просмотренные обе исходные компоновки; это **не** применение того же правила к фиктивному fixed LEFT/RIGHT PWM. |
| Обратное направление информации | **PASS только с правилами** | примечание к §2.1.6, черт.4: если inputs справа/снизу, outputs слева/сверху, на линиях выводов/связи нужны стрелки, показывающие направление, и **соответствующее обозначение функции**. |

**Отдельная важная семантика `PWM`:** в просмотренной табл.2 ГОСТ 2.743-91 отдельное `PWM` не обнаружено как стандартная функция. **§2.2.6** предписывает пояснять на поле схемы **обозначение функции, не установленное стандартом**. Следовательно `PWM` как выбранная пользователем буквенная метка — **условно допустима**, если её смысл указан (например, «широтно-импульсная модуляция»), функциональность реального прибора подтверждена. Само наличие слова `PWM` в IC не даёт типового DD/DA pinout или способа ориентации; `PWM` не следует автоматически считать частью номенклатуры табл.2.

**Обязательные / рекомендуемые / редакторские размеры:**
- **ГОСТ 2.743 §2.1.7** — определить реальный W/H из строк, числа выводов, дополнительных полей и реального шрифта; §2.1.9 чертёжный шрифт ГОСТ 2.304-81, а не CSS em. **§2.1.5** выводы на уровне границ сторон прямоугольника запрещены.
- **§2.3.12** физические номера **над линиями выводов** (у входа слева, выхода справа) или **в разрыве линии**; для top/bottom и повёрнутых полей — отдельный figure-matched контроль, нет права перенести число на боковую сторону автоматически без проверки. Правило не касается произвольного номера логического `visual_row`.
- **§2.1.8 и рекомендуемое приложение 5, табл.19 поз.1** — изображение по относительной сетке **M**, показано минимальное расстояние **≥2M**; M из формулы/микрофильмирования, **не равно безусловным 1мм/2.5мм**. Конкретное `M=2.5мм`, stroke=.3мм, pin lead length, padding and text rotation default — проектные параметры. §2.2.1: **не устанавливать произвольный предел числа символов**.
- **ГОСТ 2.759 §§1.1–1.4 и 1.8** DA — аналоговый прямоугольник, первая строка функции и разрешённые TOP/BOTTOM стороны, но **нет** отдельного разрешения `main_function_only=90/270` при неподвижной коробке.
- **Пример 4/8/14/40/64 IC:** только `TEST_IC_N`, не datasheet. Физические `PinRef` и якорные `Point` не изменяются при изменении только отображения текста. Вертикальный profile не должен переподключать физические выводы или создавать новую `Net`. Реальный шрифт измерять как ink bbox, минимум отступа по применимым положениям 2.701 и собственным отдельно заявленным editorial keepouts.
- **Требование PAINT:** сделать `text_orientation` необязательной *визуальной* настройкой в DRAFT редакторе; **нормативный clean export** должен поддерживать только source-approved orientation profiles и **fail closed** для user-only 90/270 в неизменной конфигурации. Это **не приговор самому UI**: пользовательская экспериментальная конфигурация разрешена как `DRAFT_NONNORMATIVE_DISPLAY`, но **НЕ** как автоматически соответствующая ГОСТ.

**[ГОСТ 2.721-74, табл.6в поз.8](https://ohranatruda.ru/upload/iblock/328/4294852095.pdf#page=13)** — обрыв линии с требуемой информацией о продолжении и рисунками стрелок. **Критический первоисточниковый нюанс:** **тот же стандарт в табл.6в поз.35, примечание 3** (изменённая редакция с Изм. №1,2,4, [PDF p.27](https://ohranatruda.ru/upload/iblock/328/4294852095.pdf#page=28)) **прямо допускает упрощённое изображение обрыва БЕЗ СТРЕЛКИ**. Поэтому:
- **PASS**: реализация формы со стрелкой **или** допустимого упрощённого бесстрелочного обрыва с необходимым пояснением, если выбранный профиль matches original; стрелка **не универсально обязательна** для каждого разрыва.
- **FAIL**: требовать стрелку в каждом разрыве «по ГОСТ»; требовать стрелку на каждом непрерывном участке с именем `CTRL`; считать текст `CTRL` доказательством физического соединения; считать глазной chevron физическим XP/XS.
- **BLOCKED для PR #98 SVG:** chevron-форма и пропорции не являются автоматически источниковым arrow/stub-вариантом из поз.8/35: необходимо наложение на исходный рисунок; **голден** `DRAFT_UNMEASURED_FONT` сам сообщает об отсутствии полной печатной проверки. Новый measured preview в ветке PR #98 может быть технически пригоднее, но **конкретный проверенный старый golden** нельзя сертифицировать этим одним улучшением.

**[ГОСТ 2.709-89 §5.13–5.14, черт.10–12](https://files.stroyinf.ru/Data/194/19467.pdf#page=7):**
- **§5.13** имя участка: **над горизонтальной**, **слева от вертикальной** (оговорённое исключение над линией); напечатанный `CTRL` над прямым участком **PASS по расположению**, но слово `CTRL` — проектный semantic label, не заводской physical connector.
- **§5.14** вместо имени допускаются **взаимные адреса присоединения**: на начале — адрес **конца**, на конце — адрес **начала**, выраженный буквенно-цифровым обозначением **элемента/устройства/функциональной группы** по ГОСТ 2.710. [Черт.10–11](https://files.stroyinf.ru/Data/194/19467.pdf#page=7) дают примеры типа `R1`↔`C3`, устройства + contact; **черт.12** разрешает **комбинировать имя сети с адресами**.
- На PR #98 `1/D4`↔`2/B7` — реальные **взаимные навигационные адреса страницы/зоны проекта**, потому **PASS по внутренней согласованности редактора**, но **BLOCKED как единственная полная форма адреса присоединения по §5.14**: названия страниц/зон **не идентифицируют сами по себе присоединяемые реальные элементы/контакты** `VT1.G` и `DD1.5`. При требовании §5.14 должен быть выбран конкретный source-compliant `remote_attachment` (`VT1.G` и `DD1.5`, при подтверждённом обозначении клемм/элементов), либо явно комбинированный вариант `CTRL / VT1.G [2/B7]`, `CTRL / DD1.5 [1/D4]` как **проектный пример**, требующий отдельного подписанного 1:1 листа, а не самодельный стандартный токен.
- **НЕ ПУТАТЬ** два уровня address: `sheet_address` editor/editorial ≠ `opposite_element_contact_address` normative §5.14; текст вывода `G` является проектной меткой и его реальный manufacturer's номер должен учитываться отдельно.
- Если нет явного §5.14 address, иной способ маркировки по §5.13 с требуемыми данными на месте обрыва остаётся отдельной возможностью, требующей ясного выбранного контракта и нормоконтроля.
